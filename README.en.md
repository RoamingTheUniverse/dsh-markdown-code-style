# DeepSeek Harness Markdown Code Style

**English** | [中文](./README.md)

[![npm version](https://img.shields.io/npm/v/dsh-markdown-code-style.svg)](https://www.npmjs.com/package/dsh-markdown-code-style)

A **plugin** that redesigns the style of fenced code blocks rendered from
markdown in DeepSeek Harness (dsh) conversation messages. It does not rewrite
the rendering component — instead it re-skins the component through its
documented public hooks, so every behavior other than styling is preserved:

- **Syntax highlighting** — shiki token colors and the light/dark theme sheets
  stay untouched.
- **Copy & wrap buttons** — clipboard logic and the "Copied" confirmation are
  unchanged; buttons are unified as pills: the new header uses the component's
  own SVG icons and tooltips, while the old header's text-only button gets an
  injected copy icon. Line numbers are generated by pseudo-elements, never
  enter `textContent`, so copied source contains no line numbers.
- **Streaming** — incremental highlighting of growing fences is unaffected.
- **Wrap toggle (added in 0.1.7-alpha.2)** — the header's wrap /
  keep-columns button keeps its state and behavior entirely in the component
  (including `aria-pressed` and its tooltip); the style only adds pressed-state
  feedback. With wrapping off the block scrolls horizontally and line-number
  columns stay aligned.
- **Both header variants covered** — messages use the new `CodeToolbar`
  (language label + wrap + copy); paths that do not provide `toolbarLabels`,
  such as tool cards, still use the old text banner. Each DOM has its own exact
  selectors; neither can clobber the other.
- **Sticky header** — `position/sticky`, `top`, and `z-index` are left as-is
  (original behavior), keeping compaction and turn-rail stacking intact.
- **Scrollport consumers** — consumers of `[data-code-block-content]`
  (compaction, system-prompt previews, …) keep their own layout and share only
  the scrollbar chrome.

## What's changed

- Card chrome: 14px radius, a 1px theme-tinted border, and a soft shadow (the
  compact markdown variant gets no shadow); the body surface uses the lighter
  `bg-layer-2` (pure white in light mode, one step up in dark mode), borders
  and separators use the lightest `border-l1` — a lighter look overall.
- Header: a distinct fill with a hairline separator, an uppercase tracked
  language label, a tighter rhythm, and radii nested inside the border; sticky
  behavior stays exactly as upstream.
- Code body: a 12px/20px code font that follows the content-size preference
  (was a fixed 11px); wrapping on by default with `overflow-wrap: anywhere`
  for graceful breaking (replacing `word-break: break-all`); turning the
  header's wrap toggle off switches to horizontal scrolling with columns
  intact; `tab-size: 4`; accent-tinted selection inside code; slim themed
  scrollbars.
- Line numbers: CSS counters hang off the stable `.line` structure of the
  highlighted output, using the same "block-level lines + absolutely positioned
  gutter" technique as the component's own numbering (identical across the
  streaming and settled arms; wrapped continuation lines get a hanging indent
  aligned with the code column; the component's own `lineNumbers` is never
  enabled on the markdown path, and `data-line-numbers` makes our gutter yield
  to avoid double numbering). Limitation: plain-text fences (no language or an
  unsupported language) are a single text node inside the component — there is
  no line structure to count, so they show no line numbers.

> **Compatibility**: these styles target dsh **0.1.7-alpha.2** — that release
> changed the code-card header to `CodeToolbar` (icons + tooltips) and added
> the wrap toggle; the message path and the old text-header path each have
> their own selectors, so the two structures never cross-match.

Every style value comes from theme tokens, so both light and dark themes adapt.

## Install

Install dsh first (skip if you already have it):

```sh
npm install -g @deepseek-ai/dsh@latest
```

Install this plugin (replace `web` with your profile name — existing local
profiles can be listed with `ls ~/.dsh/profiles`; common names are `web` and
`tui`):

```sh
dsh plugin --profile web add dsh-markdown-code-style
```

When installation finishes, **refresh the Harness page** to activate it.

## Update

Update this plugin to a new version:

```sh
dsh plugin --profile web update dsh-markdown-code-style
# or force-install the latest version
dsh plugin --profile web add dsh-markdown-code-style@latest
```

Update dsh itself:

```sh
npm install -g @deepseek-ai/dsh@latest
```

Refresh the page after updating as well.

## Publishing to npm (maintainer)

1. Bump `version` in `package.json` (follow semantic versioning).
2. Publish — `prepublishOnly` automatically runs the `scripts/check.js`
   preflight and aborts the publish when a check fails:

```sh
npm run check        # run the checks manually (optional)
npm publish          # publish to the registry configured in .npmrc
# for the public npm registry:
npm publish --registry https://registry.npmjs.org
```

The published contents are controlled by the `files` allowlist in
`package.json` (development files such as `scripts/` never enter the tarball).

## How it works

This is a dsh plugin package with two halves:

- **Host half** (`index.js`): a no-op — the real work happens in the browser.
- **Client half** (`client.js`): declares the browser-side module, which
  mounts a `<style>` element through `ctx.effect` and removes it automatically
  when the plugin is unloaded.

`dsh.bundle.patch` in `package.json` (pointing at `cordis.patch.yml`) declares
one plugin row to dsh's Loader — that is the entire meaning of the "bundle"
mechanism in the docs: it is simply how a plugin package declares itself, and
you never need to care about it when using the plugin. `dsh.client` declares
the loading phase and dependencies of the browser-side module.

### Where the display text comes from (for maintainers)

The plugin card's title and description come from `meta.title` /
`meta.description` inside `locale/<language>.json` (verified against dsh: this
is the only place it reads; `locale/en.json` doubles as the English fallback
and the directory anchor). **Do not add a `meta` block to `package.json` — dsh
never reads it**: the top-level `name` / `description` only act as fallbacks
when a locale field is missing, and `description` also doubles as the npm
search summary. After editing text, run `npm run check` — it validates the
locale fields together with the exports/files resolution paths.
